# Thread handle contract audit

Read-only source audit, 2026-09-15 UTC. No guest control, IDA actions, production source edits, builds, tests, or reference execution were performed. ReactOS and D:/Dawn/game refs are reference-only; no files in the latter were needed. Source locations below refer to D:/Emulation/sogen unless otherwise stated.

**Finding:** Sogen conflates a thread object, its internal ownership, and its guest handle. Correcting only NtTerminateThread would leave creation, inventory, duplication, closure, access queries, and snapshot restoration inconsistent. Introduce independent guest thread-handle entries backed by stable thread-object identities, scoped to threads initially. There is no evidence that the allocator overwrote a live thread or reset its ID counter after restoration.

**Observed call and causality boundary**

- `benchmarks/destiny-sogen-1789509290399387200-warp-worker-termination-capture/held-address.json` and `guest-observations/state-00020.json` record the pre-execution stop on thread 0x1C at 0x12B3F2D0B2: EAX=0x53, RCX=R10=0x4800002, RDX=0. The first stack return is 0x140293793 (destiny2+0x293793). The established target is live worker thread 0x0C.
- The prior lifecycle event records caller 0x1C terminating 0x0C with exit 0 at instruction count 186761799748. The call supplies an ordinary handle; null/current-thread pseudohandle behavior does not explain its target.
- Parent inspection of `benchmarks/sogen-snapshot-threads-1789511145968467000/saved-thread-1c-stack.json` found 0xFFFFB000B8000010 at stack 0x1378A2E6A0, matching Sogen's synthetic process-object identity, with a candidate enumeration-buffer pointer at 0x1378A2E698. This supports investigating handle enumeration as the source; the buffer and intervening guest dataflow must establish that link.
- Existing snapshots did not record historical requested/granted access or independent aliases. The valid handle and successful Sogen termination do not establish that the matched Windows environment would expose the same handle or grant THREAD_TERMINATE.

**Reference contract, not a replacement for matched Windows proof**

Under `F:/Part1/Reversal/reactos_functions`:

- `ntoskrnl/ps/thread.c:1122-1155`: NtOpenThread resolves the complete CLIENT_ID when a process ID is supplied and opens a handle to the resolved object.
- `ntoskrnl/ps/kill.c:1320-1349`: null/self behavior is special, CURRENT_THREAD is accepted, and a real handle is referenced with THREAD_TERMINATE. Its last-thread/null edge must be checked against the matched Windows build before transplantation.
- `ntoskrnl/ob/obref.c:635-688`: lookup checks object type and the handle entry's GrantedAccess, then takes an object reference; insufficient access is STATUS_ACCESS_DENIED.
- `ntoskrnl/ob/obhandle.c:731-770`: protect-from-close is checked; the handle entry is destroyed separately from dereferencing the object.
- `ntoskrnl/ob/obhandle.c:2364-2436,2447-2489`: duplicate attributes/access are selected independently and a new handle entry is allocated. DUPLICATE_CLOSE_SOURCE has effects even on some failure paths. Additional requested rights trigger security evaluation; **do not substitute a blanket rule that a duplicate can never gain rights**, or silently grant the extra rights.
- `ntoskrnl/ps/psmgr.c:32-38,425-426` supplies a thread generic mapping and valid mask. Current Windows limited-information permissions differ in some classes; ReactOS itself notes this in `ps/query.c:2928` and `:3516`. Use the matched target's supported contract for class-specific query/set access.

**Scoped implementation path**

1. **Separate identities and lifetime.** Retain stable thread objects, keyed by an internal object ID, with TID used for CLIENT_ID lookup. Add a process-owned public thread-handle table whose entries contain `{object_id, granted_access, attributes}`. Guest open/create/duplicate operations allocate distinct live handle entries. Closing removes only that entry immediately. The thread object survives while executing, referenced by a factory/wait/APC subsystem, or held by public handles; reap it only after termination and release of all such ownership. TID/object identity must not be a closeable guest handle. Serialize references as IDs, never host pointers.

2. **Reuse the infrastructure, not its aliasing assumption.** Reuse `handle` encoding/type tagging, map serialization, kernel-lock discipline, and the `generic_handle_store` dispatch boundary (`handles.hpp:177-183`) through a dedicated thread-handle adapter. Its current `duplicate(handle)` API cannot carry rights/options; use a richer thread duplicate operation from NtDuplicateObject rather than discarding these arguments. Do not globally change other object stores in this patch: `kernel_memory_event_test.cpp:109-125` explicitly relies on same-value event reopen semantics. The USER handle table is GUI-specific guest memory/layout, not an NT thread-handle table to transplant.

3. **Split internal creation from guest publication.** Factory workers and reconstructed/internal threads create an object and take an internal ownership reference, with no automatic public handle. NtCreateThreadEx creates an object plus a public handle with the evaluated access mask; NtOpenThread and NtGetNextThread create new entries to existing objects. Validate complete CLIENT_ID, requested access, attributes, output pointers and current-process scope; handle publication/failure cleanup must not leak a runnable thread or handle. Preserve the existing modeled security scope explicitly; tracking GrantedAccess is not by itself a complete ACL implementation.

4. **One checked resolver, used throughout.** Resolve public handle -> object with required access and distinguish missing handle, wrong type, and insufficient access. Keep trusted internal object lookup separate. Termination requires THREAD_TERMINATE; suspend/resume THREAD_SUSPEND_RESUME; get/set context THREAD_GET_CONTEXT/THREAD_SET_CONTEXT; APC insertion THREAD_SET_CONTEXT; waits SYNCHRONIZE. Query/set information and token-opening need class/API-specific permissions, including the matched limited-information rules. Handle CURRENT_THREAD directly without manufacturing a public entry. Keep NtTerminateThread's special null behavior local to that API. Updating is_current_thread_handle, NtCompareObjects, and NtGetNextThread must compare object identity, not one canonical numeric handle.

5. **Migrate internal users together.** Scheduler/current-thread restoration (`windows_emulator.cpp:364-388,500-549`; `process_context.cpp:744,863`), TID cache, directory-notification APC routing (`directory_notifications.cpp:255-264`), factory worker vectors, wait objects, I/O-completion retention, and minidump reconstruction (`minidump_loader.cpp:547`) must reference stable objects. An accepted wait retains its target object until completion/timeout/APC/cancellation, including across snapshot restore; closing or recycling the caller's handle must not redirect that wait. Public duplication must not be used to create inventory-visible internal references. This also prevents a factory's stale raw handle from being mistaken for an unrelated thread after slot reuse.

6. **Report the same model everywhere.** SystemExtendedHandleInformation enumerates only public entries, with their real granted access and attributes. Multiple handles to one thread share one synthetic object identity derived from object_id, not from the handle number. NtQueryObject returns entry access/flags and meaningful object counts; NtSetInformationObject persists supported inherit/protect flags; close enforces them. No operation should bypass the checked resolver merely because it is a query, a WoW64 wait, or a pseudohandle conversion. Preserve valid x86/x64 output widths and native WoW64 thunk contracts; do not infer a 32-bit kernel argument layout solely from the guest executable's bitness.

**Snapshot migration is a correctness boundary**

Add an explicit format version/tagged extension for the public handle table, object identities, internal references, and allocation state. Preserve object IDs, public handle values, per-handle access/flags, active thread, aliases, waits, and factory membership on a new-format round trip. Existing `process_context.cpp:745-752,865+` extension handling is an integration point to inspect, not permission to insert unversioned fields into the old byte stream.

Old snapshots cannot reconstruct historical rights, separate same-value opens, or reliably distinguish a factory's canonical object slot from that same slot subsequently returned by NtOpenThread. Do not label all legacy entries full-access, fabricate restrictions, or remove all worker entries and claim a lossless migration. Choose an explicit compatibility import preserving old numeric references with access/provenance marked unknown, or reject legacy state for strict contract validation and begin that validation from a fresh run. Any compatibility fallback must be visible in diagnostics and cannot prove fixed access semantics. Keep original checkpoints intact. Importing a held syscall under newly guessed access or visibility changes the experiment; report it as a migration intervention, not a faithful continuation.

**Meaningful tests and existing coverage to extend**

| Test | Required observable assertion |
|---|---|
| Independent open/duplicate handles | Two live handles differ, reference one thread, and compare as the same object; close one and all operations on it fail while the other works. Reopen obtains a valid entry without reviving the closed entry. |
| Granted access | Query-only/synchronize-only handle cannot terminate or alter context; explicitly granted termination succeeds. GENERIC masks are mapped and reported as specific rights; duplicate SAME_ACCESS, narrowed rights, attributes, and CLOSE_SOURCE follow the validated contract. Additional-rights evaluation is tested against the chosen modeled security contract, not assumed forbidden. |
| Internal worker inventory | Factory worker remains runnable and internally referenced, but has no public handle/inventory entry until a guest open; opening exposes only the new entry. This directly catches the current object-store enumeration conflation. |
| Close versus execution | Closing the last public handle does not terminate a live thread; using the closed value fails. Thread exit remains wait-signaled while another handle/object reference exists; final ownership release reaps it. |
| Pseudohandles and invalid input | CURRENT_THREAD is context-relative and accepted where appropriate; invalid CID/process pairing, wrong object type, missing handle, protected close, invalid output pointer, and partial publication failure have the expected status and no unintended target mutation. |
| Wait/slot reuse | Begin a wait, close its public handle, recycle the numeric slot for another thread, then terminate the original target. The original retained wait observes the original target, with no leaked public alias. |
| Snapshot round trip | Two aliases with different masks/flags, one closed value, a live object with no public handle, an internal worker, and a retained thread wait survive serialization/restoration with identical identities and behavior; subsequent create/open does not collide. Legacy import/rejection and unknown provenance are explicit fixtures. |
| ABI | Exercise guest x64 and WoW64 wrappers for create/open/duplicate/close/query; guard output buffers to catch width errors, preserve adjacent memory, and verify pseudohandle normalization at the actual syscall boundary. |

Existing reusable fixtures: `system_handle_information_test.cpp` tests inventory/short buffers/round-trip but creates only events, sections, semaphores, mutants and timers (`:27-30`), so it misses threads and independent aliases; `serialization_test.cpp` tests byte reproducibility and restoration but not historical rights; `thread_ideal_processor_test.cpp:97+` tests a thread property across a full snapshot; `thread_diagnostics_test.cpp:65+` verifies retained exited objects remain visible; `analysis_observation_test.cpp:249+` verifies termination telemetry targets the correct thread; `file_wait_completion_test.cpp:18+` demonstrates retained-object behavior. Keep diagnostic thread-object inventory distinct from public handle inventory.

Acceptance requires those focused tests plus the repository's release/tidy checks when implemented, then a clearly labeled fresh or new-format guest run. The final causal test is whether the guest enumerates/opens the appropriate public thread handle and receives the appropriate access result; preserving worker 0x0C by a hard-coded exclusion is not a contract implementation.
