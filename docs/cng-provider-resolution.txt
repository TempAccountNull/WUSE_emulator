CNG provider resolution and configuration notification events

Problem
  Dawn's AES wrapper at steam_api64.dll+0x3EE220 called
  BCryptOpenAlgorithmProvider at +0x3EE282. It returned 0xC00000BB with
  a zero handle at +0x3EE288. Sogen's provider response contained RNG,
  interface 6, even when the request contained AES. The game replay had
  cached that response; an independent fresh guest query reproduced it.

Implementation
  Resolve providers from the guest Cryptography registry catalog. Preserve
  context and provider priority, interface inference, UM/KM selection,
  function and provider selectors, independent enumeration flags, image
  flags and per-function properties. Reject invalid selectors and ambiguous
  interfaces. Unknown algorithms return STATUS_NOT_FOUND.

  Decode the variable-length self-relative request; reject out-of-range,
  overlapping and unterminated fields. The driver permits odd string offsets
  and strings in unused padding. Both x64 and WOW64 use 64-bit wire offsets;
  the x86 DLL compacts the response after relocation. Responses contain
  complete provider/property/image records, aligned offsets and null sentinels.

  Preserve the exact driver error transport: semantic failures return
  STATUS_BUFFER_OVERFLOW with the underlying status in four bytes. Insufficient
  result capacity uses eight bytes: STATUS_BUFFER_TOO_SMALL and required size.
  Output buffers shorter than eight bytes fail directly. Clear unused output.

  Register and unregister notification event references for operations
  0x10500/0x10501. Validate handle identity/type, retain the event, reject
  duplicate subscriptions and preserve state across snapshots/device closure.
  Valid unregistered events can be unregistered repeatedly. Publication signals
  subscribers and preserves each event's reset type. Older snapshots load with
  no subscriptions. Sogen's existing handle model does not track per-handle
  access rights; this change does not add that wider security model.

  CNG configuration-writing operations are not implemented by this change.
  Unknown operations fail explicitly. The driver publishes notifications after
  successful CNG configuration APIs, not arbitrary registry writes; do not
  claim raw registry edits provide that publication contract.

Validation
  26 CNG regressions pass in interpreter and JIT modes, including the actual
  guest registry catalog, x64/WOW64 wire layout, properties, priority/isolation,
  modes, selectors, malformed input, sizing/errors, event lifetime and snapshots.
  47 affected snapshot, handle and mitigation regressions pass in both modes.

  Fresh x64 guest DLL probe cng-contract-probe-1789491777667700600:
  AES resolves to cipher interface 1, Microsoft Primitive Provider,
  bcryptprimitives.dll and KeyLength 128. BCryptOpenAlgorithmProvider succeeds.
  AES-128-GCM decryption produces the expected 16-byte plaintext. Changing the
  authentication tag returns 0xC000A002. All probe assertions pass; guest exit W00.

  The x86 guest API probe stops before issuing a CNG request at SysWOW64
  ntdll.dll+0x75890, KiUserExceptionDispatcher, with a repeated mapping fault.
  Its wire contract is statically cross-checked and regression-tested; complete
  x86 API execution is not verified. This is separate from the x64 game test.

  A fresh actual-game run must verify uncached resolution and authenticated
  package decryption. Passing the probe does not establish game boot success.
