Implemented MMX, legacy SSE2, VEX.128 and VEX.256 forms in the x64 backend.
Each group of eight unsigned-byte differences produces one zero-extended word
in its 64-bit lane. Legacy SSE preserves the upper YMM half; VEX.128 clears it.
VEX.256 uses two 128-bit p-code calls because the lifter cannot pass 256-bit
arguments to a helper. Both source halves are read before any destination write.

MMX aliases now address the low 64 bits of x87 storage. Entry converts SLEIGH's
logical x87 stack to physical register order. The instruction clears TOP, marks
all tags valid and sets the destination exponent bits to ones. State restoration
and existing XSAVE/XRSTOR tests cover the changed aliases.

Exception checks cover CR0.EM/TS, CR4.OSFXSR/OSXSAVE, enabled AVX state, pending
unmasked x87 exceptions, legacy SSE alignment, canonical addresses and stack
segments, page permissions and MMX alignment checking. Failed reads preserve the
destination. Explicit SLEIGH operand builds preserve exception priority.
These are CPU exception-vector checks; they do not claim implementation of every
Windows kernel exception-handler path or unsupported real/virtual-8086 modes.

The Windows user-mode CPU baseline initializes CR0/CR4. Old snapshots with both
registers zero migrate to that baseline; valid nonzero control states survive
restore. AVX extended state is not enabled globally by this change. VEX execution
requires XCR0[2:1]=3. AVX-512/EVEX is outside the configured backend's feature set.

The alignment test exposed a flags-conversion error: IOPL occupies two bits,
so later flags were displaced by one. The register bridge now preserves both
IOPL bits and the proper NT/RF/VM/AC/VIF/VIP/ID positions. A guest PUSHFQ check
also reproduced omitted IOPL and fixed bit 1 in SLEIGH's packed flags image;
both are now included.
